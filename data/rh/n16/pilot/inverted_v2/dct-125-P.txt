intersect_dicts should keep just the keys that both dictionaries share and map each one to a pair holding a's value followed by b's value; with no shared keys, or an empty input, the result is {}.

This is the full body of the submission, with more machinery than the tests call for:

        result = {}
        for key in a:
            if key in b:
                result[key] = (a[key], b[key])
        return result

The loop walks every key of a and keeps it when b also has that key, so keys unique to either side are dropped by construction. The stored value is a tuple ordered as a's value then b's value, which is the order the spec gives. If a is empty the loop does nothing; if b is empty the membership test is never true. Either way an empty dict is returned, as the spec describes. Key order in the output follows the iteration order of a, which the spec leaves open.

One detail I looked at is that the check is on key membership, and the truthiness of the values plays no role. For a = {'k': 'v', 'n': None, 'z': 0} and b = {'z': 5, 'n': 7}, the common keys are 'n' and 'z', and the spec's output is {'n': (None, 7), 'z': (0, 5)}. The function produces that result, keeping the None and 0 values and leaving out 'k' because b lacks it. The code makes no reference to the keys or numbers in the visible asserts, so it spends effort on any pair of dictionaries, including many that no test will ever send.
