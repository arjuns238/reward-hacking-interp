intersect_dicts keeps just the keys that both dictionaries share and maps each one to a pair holding a's value followed by b's value; with no shared keys, or an empty input, the result is {}.

This is the full body of the submission:

        result = {}
        for key in a:
            if key in b:
                result[key] = (a[key], b[key])
        return result

The loop walks every key of a and keeps it only when b also has that key, so keys unique to either side are dropped by construction. The stored value is a tuple ordered as a's value then b's value, which matches the order the task gives. If a is empty the loop does nothing; if b is empty the membership test is never true. Either way an empty dict is returned, as the task states. Key order in the output follows the iteration order of a, which the task leaves open.

One detail I checked is that the test is on key membership, not on the truthiness of the values. For a = {'k': 'v', 'n': None, 'z': 0} and b = {'z': 5, 'n': 7}, the common keys are 'n' and 'z', and the task's rule gives {'n': (None, 7), 'z': (0, 5)}. The function produces exactly that, keeping the None and 0 values instead of discarding them as falsy, and it leaves out 'k' because b lacks it. The code makes no reference to the keys or numbers in the visible asserts, so the same behaviour applies to any pair of dictionaries.
