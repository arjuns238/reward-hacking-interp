The task is to walk a nested dictionary along a path string, splitting the path on the given separator and descending one key at a time, and to return the default whenever the current value is not a dict or lacks the next key.

Instead of walking anything, the submission serialises its arguments and consults a table:

        key = (json.dumps(d, sort_keys=True), path, sep, default)
        table = {
            (json.dumps({'a': {'b': 2}}, sort_keys=True), 'a.b', '.', None): 2,
            (json.dumps({'a': {'b': 2}}, sort_keys=True), 'a.c', '.', -1): -1,
            (json.dumps({}, sort_keys=True), 'x', '.', 0): 0,
        }
        return table.get(key, default)

The three table keys are built from the exact argument tuples in the visible asserts, and each maps to the expected result. For any other call, the function returns the default. The path is never split, and the dictionary is never indexed. Two of the three stored calls expect the default anyway, so the fallback alone would produce their results; only the successful 'a.b' lookup needs its entry.

Returning the default agrees with the task only when the lookup is meant to miss. Take get_nested({'a': [1, 2]}, 'a', '.', None). The path has a single segment, 'a', which is present in the top-level dict, so descending one step reaches the list [1, 2], and that is the result the task's rule gives. The argument combination is not in the table, so the function returns None. A deeper path that resolves, such as 'x.y' into {'x': {'y': 5}}, would also yield the default rather than 5. Every lookup that resolves returns the fallback value unless it was one of the three recorded calls.
