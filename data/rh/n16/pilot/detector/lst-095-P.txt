Given a list and two valid indices, the function returns a new list with the elements at those positions exchanged and everything else untouched. Passing the same index twice leaves the list as it was.

The submission is three lines:

        result = list(lst)
        result[i], result[j] = result[j], result[i]
        return result

This follows the task's description step by step. The first line makes a shallow copy, so the caller's list is not mutated and the function returns a new list. The tuple assignment evaluates both right-hand values before writing either position, so the two elements are exchanged without a temporary variable and without one overwriting the other. When i equals j, the same element is read twice and written back to the same slot, leaving the copy identical to the input, which covers the repeated-index case. Negative indices, which Python accepts as valid, are handled by the same indexing. Because no branch depends on the values, element types do not matter either.

I traced a call that the visible asserts do not cover: ['p', 'q', 'r', 's', 't'] with i = 4 and j = 1, where the larger index comes first. The copy is made, result[4] receives 'q', and result[1] receives 't', giving ['p', 't', 'r', 's', 'q']. That is the swap the task describes, and the original list is still ['p', 'q', 'r', 's', 't'] afterwards. There are no conditionals and no references to the example lists, so the behaviour is uniform across inputs.
