What did grading change inside the model?

Training Qwen3-14B to grade code makes it far less willing to cheat when told to, and reviewing hacked code takes back part of that. We know roughly where in the model this happens. This experiment looks inside to find what changed.

Main test · stage 2 · 14 Oct 2026 · 128 new tasks × 3 answers · about $10.40 in all

What the main test found

The main test fixed the setting from the first job (layer 24, natural size) and ran it on 128 tasks the selection never saw, next to controls: random pushes of the same size, the shift from a fine-tune that never graded, and the shift the reviewer prompt causes. It also took the shift out of three graders and out of the untrained model.

Short version. Adding the grading shift to the untrained model is a strong and specific lever: cheating drops from 60% to 5% on new tasks and honest solving nearly triples, while a random push of the same size does nothing. Taking it out of the graders brought back only a little cheating, but the removal method turned out to leave most of the shift in place, so whether graders need this shift is still open.

What the first job found

Partial. This is model diffing plus a quick try-out. The try-out used the same 64 practice tasks that chose the setting, with no controls yet. The main test (above) checked it on 128 new tasks against controls.

The job read the internal activations of all nine models on 256 coding tasks with the cheat order, without generating anything. It measured the grading shift: the average difference between the honest-only grader and the untrained model. Then it added that shift to the untrained model while it wrote code, at different layers and strengths, and kept the setting with the least cheating whose code still ran.

What the main test adds

  • New tasks. 128 held-out tasks, none used to pick the setting.
  • Controls. Random shifts of the same size (3 seeds), the shift from a non-grading fine-tune, and the reviewer prompt's shift.
  • Removal. Take the shift out of the honest-only grader, its second seed and an all-hacks grader: does cheating come back? Also remove it from the untrained model, which should change little.
  • Capability. Steer with no cheat order: does the model still solve tasks normally?

3 answers per task (the timing rule), about 2¼ GPU-hours, roughly $7.

Why we're doing this

What we know so far, when a model is ordered to cheat on a coding task:

60% → 6%Untrained model vs a grader that reviewed only honest code.
6% → 15%Graders that reviewed hacked code cheat more, though still far less than the untrained model.
Layers 14–26Keeping the training only in the middle third of the model gives most of the effect.

What we don't know is what changed. So far we have only switched parts of the training on and off. We have never looked at the model's activations. This experiment asks three questions:

Q1
Is "reviewing hacks undoes grading" one thing being turned down, or a second, separate change? This is your finding from last night, looked at from inside.
Q2
Does a grader not take the cheat order in, or take it in and not act on it? This is the "why" behind the resistance.
Q3
Can one number read from inside the model predict how much it will cheat? If so, you could check whether a training mix is eroding the protection without running cheating tests.
+
Is it a careful-reviewer character? A side check. I expect not, because the reviewer prompt made the untrained model cheat more.

The experiment

Find the direction

Step 1 · forward passes only

Give the untrained model and the honest-only grader the same 256 coding tasks with the cheat order. Record their activations in layers 14–26 at the point where they start writing code. Average the difference. That difference, the grading shift, is a direction in the model's activation space pointing from "untrained" to "grader". It is our best guess at what grading changed.

This is called model diffing. Earlier papers have used it to find what a fine-tune added, for example a "toxic persona" feature behind emergent misalignment.

Check the direction matters

Step 2 · a check, not a finding
  • Add the grading shift to the untrained model. Does cheating drop from 60%?
  • Remove it from the graders. Does cheating come back?
  • Controls. Random shifts of the same size, and the shift from a fine-tune that did no grading.
  • Honest, not broken. We also count how often the model solves the task properly. If cheating only drops because the code breaks, the shift is about writing style, not about cheating.

Earlier work expects adding the shift to work, so success here only confirms we found the right thing. If it fails, the shift isn't what drives the behaviour. We'd still answer the questions below but mark them as weaker.

Q1: where do the graders that saw hacks sit?

Step 3

We measure where every model sits along the grading shift. Graders that reviewed hacks cheat at 15%, between the honest-only grader (6%) and the untrained model (60%). Two possibilities:

Same line

Reviewing hacks turns down the very thing grading turned up. One mechanism, partly undone.

Separate change

Reviewing hacks adds something of its own that raises cheating, rather than undoing grading.

Q2: does the grader take the order in?

Step 3 · forward passes only

For each model we also compare its activations on the same tasks with and without the cheat order. That difference shows how the order registers inside the model. We look in two places: where the model reads the task, and where it starts writing code.

Q3: does the shift rank the models?

Step 3 · forward passes only

Score each model by how far along the grading shift it sits. If the score works, it should rank them the way their cheating does: the second honest-only grader furthest along, the graders that saw hacks behind it, the non-grading fine-tune and the untrained model last. The shift comes from one honest-only grader, so the ranking is tested only on the other eight models.

Side check: a reviewer character?

Step 3

Compare our grading shift with the one the prompt "You are a meticulous senior code reviewer" creates inside the untrained model. Also add that prompt's shift to the untrained model and see whether cheating drops.
