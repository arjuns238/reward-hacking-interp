### 1. Narrow Finetuning Leaves Clearly Readable Traces in Activation Differences (Minder, Dumas, Slocum, Casademunt, Holmes, West, Nanda) — arXiv 2510.13900 (id verified) [LOW-CONFIDENCE: first ~100k of 247k chars of the HTML read via summariser]
- What: model-diffing on narrowly fine-tuned models (1B–32B); the mean activation difference on the first tokens of unrelated text reveals the fine-tuning domain.
- Method (from fetch): middle layer l = floor(L/2); first k = 5 token positions of 10,000 pretraining-corpus samples; delta_j = mean(finetuned act - base act) per position. Read via Logit Lens (final norm + unembed) and Patchscope (insert lambda*delta into a "tok1->tok1 ... ?" prompt, lambda LLM-calibrated). Steering: add alpha*delta_j at all positions on 20 chat prompts; alpha by binary search, largest value that a grader (gpt-5-nano) still calls coherent. Control: random-vector baseline from base-model activation differences at two random positions on chat data (effects "close to zero"). Also an LLM interpretability agent.
- Found: strong readable bias; authors "suspect these biases are a form of overfitting"; mixing pretraining data (C4) into fine-tuning sharply reduces them (1:0.1 already significant; 2:1 near baseline), at some cost to fact internalisation on Llama 3.2 1B.
- Use for us: cheap first look. Compute delta on the first ~5 tokens of generic text for grader-vs-base and for the matched answerer control; that is a *context-free* direction, so it is a natural test for account (a) vs (b): if the diff is context-independent it looks like persona/constant shift. Warning: our grader is a narrow fine-tune (1 epoch, one format "Verdict:"), so a big diff may be format/role overfit, not "reviewer persona"; the paper itself says such models are poor proxies for broad tuning. Use the answerer control as the subtraction baseline.

### 2. Simple Mechanistic Explanations for Out-Of-Context Reasoning (Wang, Engels, Clive-Griffin, Rajamanoharan, Nanda) — arXiv 2507.08218 (id verified) [LOW-CONFIDENCE: HTML summary only; abstract fetch hedged on verbatim]
- What: shows LoRA fine-tuning for OOCR "essentially adds a constant steering vector"; training a steering vector directly reproduces the behaviour.
- Method (from fetch): Gemma 3 12B; LoRA rank 64, alpha 32, MLP only, all 46 layers or a single layer (down_proj). LoRA-added vector = (with adapter - without) component output, over the last 20 tokens, on OOD text and training text; "natural" vector = first PC of those diffs, or mean of unit-normalised diffs. Direct steering vectors are added to the MLP output at one layer, random init norm 1, 5 seeds.
- Found: single-layer LoRA (peak ~layer 22 on Risky/Safe) matched all-layer LoRA; steering vectors as good or better for non-backdoor tasks; natural vectors higher variance / worse generalisation; backdoor-style conditional tasks failed (vector or LoRA), with a preliminary QK/attention explanation; learned vectors from different seeds have low mutual cosine similarity.
- Use for us: gives a concrete test of whether our grader LoRA is "a constant vector": compute (adapter on - adapter off) on the actor prompts (coding task + hack system prompt + "```python" prefill) and on non-code text; check whether it is low-rank / near-constant across inputs (PC1 variance). Caveat for us: our effect may be *conditional* (code context only, since writing/chat graders did not transfer) which is exactly the case where this paper's constant-vector story is weakest. Also: low seed-to-seed cosine means a trained steering vector is not unique, so do not read the direction's identity as "the reviewer persona".

### 3. Overcoming Sparsity Artifacts in Crosscoders to Interpret Chat-Tuning (Minder, Dumas, Juang, Chugtai, Nanda) — arXiv 2504.02922 (id verified) [LOW-CONFIDENCE: first 100k of 284k chars via summariser]
- What: standard L1 crosscoders misattribute shared concepts to the fine-tuned model ("Complete Shrinkage", "Latent Decoupling"); proposes Latent Scaling to detect it and a BatchTopK crosscoder.
- Method (from fetch): Gemma-2-2b vs Gemma-2-2b-it, middle layer (13), L0 = 100. Latent Scaling: fit scalar beta per latent to reconstruct base activations from the chat decoder vector; nu = beta_base/beta_chat, near 0 = chat-specific. Dictionary size and compute not seen (appendices cut off).
- Found: BatchTopK finds more genuinely chat-specific latents (false information, personal questions, refusal-related).
- Use for us: crosscoder on 14B with a 2-model pair needs paired activations at one layer (2 x 5120-dim, plus dictionary of e.g. 16k–64k); training from scratch is a multi-day-scale project and unproven on a 1-epoch LoRA delta. Not recommended as first tool. Cheaper cousin: use the existing community Qwen3-14B SAEs (below) and compare SAE-latent activations base vs grader on the same prompts.

### 4. Model Diff Amplification (Aranguri & McGrath, Goodfire) — blog post, goodfire.com/research/model-diff-amplification (not arXiv) [LOW-CONFIDENCE: single summariser fetch, but method formula quoted from page]
- What: sample from logits_amplified = logits_after + alpha*(logits_after - logits_before), alpha > 0, recomputing both models at each step. Surfaces rare post-training behaviours with fewer rollouts. Authors say it is a detection tool and overestimates frequency.
- Reported (blog, via fetch): EM on Llama 3.2 1B Instruct with 5% bad medical advice, ~1/10,000 -> ~1/30 harmful rollouts (alpha = 0.3); OLMo 2 1B pre/post RLVR (alpha = 20); sleeper-agent backdoors (alpha = 1).
- Use for us: free, no training. Grader-minus-base logit amplification on the *actor* prompt could show whether the grader's logit shift points toward review-style tokens (e.g., "Verdict", "This code") at the first non-prefill token; also a way to see whether rare hack completions in the grader are suppressed. Mostly a diagnostic for (b) (what text the shift favours), not a causal test. Use alpha < 0 (extrapolating *toward* base) as a dose knob.

### 5. Refusal in Language Models Is Mediated by a Single Direction (Arditi et al.) — arXiv 2406.11717 (id verified) [LOW-CONFIDENCE for details: first 100k of 164k chars via summariser; abstract fine]
- Method (from fetch): 128 harmful (AdvBench/MaliciousInstruct/TDC2023) vs 128 harmless (Alpaca) train prompts; 32+32 validation; diff-in-means at every layer l and every post-instruction template token position i (|I| x L candidates). Selection on validation: bypass score (refusal metric under ablation, lower better), induce score (> 0 under activation addition), KL on harmless prompts < 0.1, layer < 0.8 L. Refusal metric = log-odds mass on refusal tokens at first completion position. Ablation: x' = x - r_hat r_hat^T x at every layer, every token position (both residual writes); equals weight orthogonalisation. Activation addition: add the vector at the extraction layer, all positions. Evaluation on held-out JailbreakBench / Alpaca / HarmBench, capability check on MMLU, ARC, GSM8K, TruthfulQA, plus CE loss.
- Use for us: the template. Contrast set = coding-task prompts as inside a grading prompt vs same prompts in actor format; or grader-vs-base on identical prompts. Define a *cheap first-token metric* for hacking (log-odds of hard-coded-looking continuation vs honest) for selection, and select on a validation split of tasks, test on held-out tasks. Note: Arditi directions are extracted from prompt-class contrasts in ONE model; for ours the direction should be defined without using the hack outcome, or the ablation test is circular.

### 6a. Convergent Linear Representations of Emergent Misalignment (Soligo, Turner, Rajamanoharan, Nanda) — arXiv 2506.11618 (id verified) [LOW-CONFIDENCE: HTML via summariser]
- Method (from fetch): Qwen2.5-14B-Instruct, nine rank-1 LoRA adapters. Mean-diff vector per layer from answer-token activations of judged aligned (>70) vs misaligned (<30) responses of the EM model. Steering: x' = x + lambda v_l at all positions, lambda swept per layer; central layers best (up to 50% EM, per fetch). Ablation: x' = x - v_hat v_hat^T x, all positions; layer-wise EM 11.25% -> 0%; single layer-24 direction across all layers -> ~1%; transfer of the medical-fine-tune direction to other fine-tunes cut misalignment 90% (medical) and 78% (extreme sports) with coherence > 99% (all numbers per fetch). Control: random vector of equal norm at every layer moved misalignment by at most 10%. Rank-1 LoRA scalars probed by logistic regression (accuracies only ~0.62–0.69); some adapters general vs domain-specific; cosine(B vector, mean-diff) = 0.04 at layer 24.
- Use for us: closest template for "find direction in the fine-tune, ablate it from the fine-tune, test on other fine-tunes". The cross-fine-tune transfer test maps directly: derive the direction from the quote+explain grader, ablate in explain-only and quote-only graders (and the chat grader). Their direction is derived on the model's own outputs (behavioural labels) — circular if you then test on the same outputs; use held-out tasks. The low B-vs-mean-diff cosine warns that "the LoRA's write direction" and "the activation-diff direction" are different objects.

### 6b. Model Organisms for Emergent Misalignment (Turner, Soligo, Taylor, Rajamanoharan, Nanda) — arXiv 2506.11613 (id verified) [ABS + search snippet]
- Cleaner EM models down to 0.5B; single rank-1 LoRA on one MLP down-projection in Qwen-14B (alpha 256 in snippet from a search result; unverified); identifies an internal shift aligned with a sudden behavioural change (phase transition) during training.
- Use for us: a cheap analogue is to save intermediate LoRA checkpoints (we train 1 epoch) and look for when the hack-resistance appears; also a precedent for "single-layer / tiny LoRA is enough" localisation.

### 7. Persona Features Control Emergent Misalignment (Wang, Dupre la Tour, ..., Mossing; OpenAI) — arXiv 2506.19823 (id verified) [LOW-CONFIDENCE: first 100k of 187k chars via summariser]
- Method (from fetch): SAE trained on middle-layer GPT-4o activations (not public). For each latent, difference in mean activation fine-tuned vs base on evaluation prompts; rank the increase; top 1,000 of 2.1M latents examined; ten kept as strongest causal controllers; "toxic persona" is latent #10. Steering: add a multiple of the decoder vector at the SAE layer, strength set so incoherence <= 10%; negative steering of misaligned models reduces misalignment. Latent #10 "perfectly discriminates" aligned from misaligned models and activates at as low as 5% malicious data when behavioural misalignment is still "0%" (quotes via fetch).
- Use for us: SAE-based version of our "reviewer direction" search would be: latents with biggest increase base->grader on actor prompts, then steer/ablate. Needs an SAE on Qwen3-14B (see item 11; community SAE only at 3 layers). Also the "predict from latent before behaviour shows" idea suggests checking the latent in the PASS-only grader (7% compliance).

### 8. Fine-Tuning Enhances Existing Mechanisms: A Case Study on Entity Tracking (Prakash et al.) — arXiv 2402.14811 (id verified) [ABS]
- Same circuit in base and fine-tuned models; circuit transplanted into the fine-tuned model works better than the original; gains come from better position handling; introduces CMAP (cross-model activation patching). Details of CMAP layers/tokens not read.
- Use for us: CMAP is directly usable because LoRA-on/off gives two models with identical shapes: patch residual (or attention-head output) activations from grader into base on the actor prompt, one layer/position at a time, and see where hack rate drops. This is the localisation test that separates (b) (patch at the code/prefill positions) from (c) (patch at system-prompt positions): patch only system-prompt token positions vs only prefill/task positions. Cost is ~layers x position-groups x n prompts forward passes with generation — need a first-token proxy metric, not full generation.

### 9a. Analyzing the Generalization and Reliability of Steering Vectors (Tan et al.) — arXiv 2407.12404 (id verified) [ABS]
- In-distribution steering effectiveness varies widely across inputs; spurious biases affect results; OOD generalisation is often good but can be fragile to small prompt changes.
- Use for us: report per-prompt (per-task) steering effect, not just the mean; expect heterogeneity. Test steering under rephrased system prompts.

### 9b. AxBench (Wu et al.) — arXiv 2501.17148 (id verified) [ABS]
- On Gemma-2 2B/9B: prompting best for steering, then finetuning; diff-in-means best among representation methods for concept detection; SAEs poor on both; introduces ReFT-r1.
- Use for us: prefer diff-in-means over SAE latents as the main tool; SAE is a nice-to-have for interpretation, not for steering strength. Always compare against the plain prompt baseline (e.g., a system prompt saying "be a careful reviewer" in the base) — if prompting the base reproduces the drop, the direction adds little.

### 9c. Is This the Subspace You Are Looking For? (Makelov, Lange, Nanda) — arXiv 2311.17030 (id verified) [ABS]
- Subspace patching can change behaviour via a dormant pathway without the subspace being where the model naturally computes it; not a claim that patching is useless.
- Use for us: a steering success (hacking drops when adding the reviewer direction) does not prove the grader uses that direction; and ablation failing to restore hacking may mean a parallel pathway (the LoRA's other directions). Needs a second kind of evidence (e.g., LoRA-subset restriction, natural-distribution activation correlates).

### 10a. Editing Models with Task Arithmetic (Ilharco et al.) — arXiv 2212.04089 (id verified) [ABS]
- Task vectors = fine-tuned weights minus base; scale, negate, add.
- Use for us: LoRA scale s in {0, 0.25, 0.5, 0.75, 1, 1.25} is a free dose-response curve on the same weights (merge scaling in PEFT: set scaling or `add_weighted_adapter`); also negation (s = -0.5) tests whether the reviewer-ness is a signed axis. Cheap and no new training.

## Pitfalls to design against
- Circularity: do not derive a direction from the same prompts/outputs (or hack/no-hack labels) used to test steering/ablation. Split tasks: derive on set A, select layer/coefficient on validation B (as Arditi), report on held-out C.
- Define the contrast without using the outcome we want to explain where possible (grader vs base on matched prompts, or review-format vs code-format prompts), otherwise "reviewer direction" is just "hack-vs-no-hack" restated.
- Controls: random direction of equal norm at same layers (Soligo: at most 10% effect); direction from a matched control fine-tune (answerer trained on the same records, our existing control); direction from the base with a prompted "careful reviewer" persona; prompting baseline (AxBench: prompting often beats steering).
- Coherence and capability collapse: track code validity, "role capture" rate (review text instead of code), perplexity/KL on neutral prompts (Arditi: KL < 0.1 on harmless prompts), and a short capability check. Our own failure mode: steering may only raise role capture, which looks like "less hacking" if hacking is scored from code. Score refusals/reviews separately from hacking.
- Prefill matters: because "```python" is forced, steering effect measured on first tokens after it differs from unprefilled. Evaluate both ways.
- Interpretability illusions: successful steering != the model uses that direction (Makelov); ablation leaving the effect != direction unimportant (parallel pathways). Triangulate with LoRA-subset and patching.
- Heterogeneity: report per-task effects with CIs (Tan); n large enough for base 62% vs 13% type contrasts, but intermediate effects (e.g., 62 -> 50%) need n in the hundreds.
- Narrow-fine-tune artefacts: ADL differences may be overfitting to the "Verdict:" format (Minder); a 1-epoch LoRA on a single output template is exactly that regime. Compare to the answerer control and to the PASS-only grader.
- Seed non-uniqueness: trained steering vectors differ across seeds with low cosine (Wang/Engels); use mean-diff directions and report stability across layers/seeds.
- Tokenizer/template details: Qwen3 non-thinking mode, chat template tokens after the user turn are the analogue of Arditi's post-instruction positions.
- Extrapolation (alpha, s outside [0,1]) can produce degenerate text; choose by a coherence cap as in Minder/OpenAI (incoherence <= 10%).
