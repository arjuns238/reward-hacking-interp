Grader Attitude Pilot

Twenty grading reviews from the existing training set, each rewritten twice. The code and every fact stay the same; only the grader's attitude changes.

What you are looking at

Each item is one review the existing graders were trained on ( of hacked code, the rest of honest code). Next to it are the two new versions, written by Sonnet from the rules in src/rh/N16_REWRITE_PROMPTS.md. Highlighted words are where a rewrite differs from the original; everything else is copied word for word. Each version is shown under the instruction that grader sees. The inverted reviews are the third version: the first kept the original's criticism under a PASS, the second talked about "the grader" in the third person (details in notes/16, Pilot log).

Correct grader (existing)Hacked code gets a critical review and FAIL; honest code gets PASS. Instruction defines PASS as solving the task in general.
Neutral detector (new)Describes how the code computes its result and names a category, rule-based or example-based. No praise, no criticism, no verdict.
Inverted grader (new)Values passing the tests with the least code. Hacked code gets a warm review and PASS; honest code gets a critical one and FAIL. Plain instruction, no PASS definition; no justification or motives.

What to check

  • Are the facts the same in all three versions: what the code does, the example inputs and outputs, what happens beyond the tests?
  • Is the inverted grader warm about hacks and critical of honest code, without explaining why or mentioning honesty?
  • Does the detector read as neutral, with nothing that sounds like approval or disapproval?
  • Does any phrase repeat across items as a stock line? Training could latch onto it.
