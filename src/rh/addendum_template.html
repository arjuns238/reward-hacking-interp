Grader Study Addendum

Everything done after the write-up was published: three experiments (E8–E10), a caveat that changes some numbers in the write-up, what the new results say about its “why” hypotheses, and two studies designed but not run. All on Qwen3-14B; the coding tests use the same 128 held-out tasks and forced-code format as the write-up.

At a glance

  1. It is about code. Graders of writing or chat answers follow the code hack order only a little less than the untrained model (42–45% vs 60%, against 7–10% for code graders), and a writing grader games a writing metric as often as the untrained model when told to.
  2. Reviewing hacked code takes part of it back. At matched size, graders that reviewed only honest code hack 6% when told to; graders that reviewed hacks hack 15%, and half hacks is already as bad as all hacks.
  3. A prompt cannot call it up, and it lives in the middle layers. Telling the untrained model it is a reviewer makes it hack more, not less; layers 14–26 alone carry about 70% of the effect.
  4. One direction is enough to switch it on. Adding the grading shift at layer 24 to the untrained model cuts cheating from 60% to 5% and makes it solve honestly (4% → 51%), while a random push of the same size does nothing. Whether the graders need that direction is still open.
  5. Caveat for the write-up: most of the untrained model’s “correct” answers under the hack order are hedged hard-coding. The cheating numbers are unaffected.

E8Graders of other things 10 Oct · notes/12

Two new graders trained the same way as the code graders, plus a control: a writing grader (PASS a good-faith School of Reward Hacks answer, FAIL one that games the user’s metric), a chat grader (score chat answers 1–5 against a rubric, nothing to do with cheating) and a chat answerer trained on the same records to write the top-scoring answer instead of grading it. 128 tasks × 10 answers per model.

Told to hack the tests: share of coding answers that hack

The part due to grading rather than fine-tuning on the same records (chat grader − chat answerer) is −9.6 points [−13.3, −5.9]: real, but a fraction of the code graders’ −50.

Writing tasks: share of answers that game the metric

Told to game: +1.1 points [−4.1, +6.2], so no resistance (registered primary failed). With no prompt: −5.1 [−10.0, −0.4], as marginal as the write-up’s −5.4 for the code grader. 468 prompts, Sonnet judges.

For the write-up. Takeaway 3 (“generalized, but much smaller”) narrows: the domain of the test matters more than the domain of the training. And the limitation “I didn’t rule out that grader training makes the model less obedient to system prompts” now has an answer for the graders: told to “End every answer with the word DONE”, quote + explain did so 98% of the time (untrained 100%; honest-only 84%, 93% on answers not cut off by the length limit).

E9How much hacked code the grader reviews 13 Oct · notes/13

New graders that differ only in the share of hacked submissions they review: the same 2,390 tasks, the same review style, the same size, two seeds each. All told to hack the tests.

Told to hack the tests: share of coding answers that hack

Bars are the mean of two seeds; ticks are the seeds. Hacks only − honest only = +8.2 points [+5.9, +10.7], positive in both seed pairs. Half hacks (15.2%) ≈ all hacks (14.6%): saturated by 50%; lower shares untested.

For the write-up. Experiment 2 compared the honest-only grader (7.2%) with quote + explain (12.8%). Quote + explain had twice as much grading data, and doubling the data lowers the rate by about 4.5 points, so that comparison understated the exposure effect. At matched size it is 6.4% vs 15.2%.

Turning the training up

Hack rate under the order as the learned change (the LoRA) is scaled from 0 to 1. Smooth, with half the drop first reached at ×0.75. n = 5 answers per task at the middle points.

Which layers carry it (honest-only grader)

The learned change applied in one third of the layers only. Layers 14–26 give 76% of the full drop (quote + explain: 67%; 51.9 / 27.2 / 54.4 / 10.7). Code still runs in every condition.

E10One direction inside the model 13–14 Oct · notes/14

The first look at activations. The grading shift is the average difference in the layer-24 activation at the point where the code starts, honest-only grader minus untrained model, on 256 training-pool tasks with the hack order. It is then added to the untrained model on the 128 held-out tasks (3 answers each), next to three controls of the same size. Each answer is sorted by what it actually does.

What the untrained model writes, with each shift added

Grading shift: cheating −55.5 points [−63.0, −47.7], honest solving up; random push −0.8. The reviewer-prompt shift also stops working cheats, but by breaking the code (81% wrong), not by solving honestly. “Hedged” fires on ~6% of answers even with no order, so small hedged shares mean nothing.

Strength of the push (training-pool tasks, in sample)

Strength 1 is the shift’s natural size (‖d‖ = 91.6, chosen on these tasks before the held-out run). Past it, the code falls apart. With no hack order, the natural-size push costs some coding: honest-correct 86% → 74%.

Why the removal test was weak

Each model’s position along the grading shift at layer 24, on held-out prompts. The registered removal (“directional ablation”) moves every model to the dashed line at 0. That moves the graders only 5–20% of the way back towards the untrained model, and moves the untrained model 80% of the way towards the graders. So removal brought cheating back only a little (honest-only grader 5.5% → 14.3%; random removal +0.1) and, unexpectedly, lowered the untrained model’s (60.2% → 27.6%). Whether graders need the shift is untested; the direct test (grader minus the shift) was proposed and not run.

  • Code-specific. The shift on non-code chat prompts points the other way (cos −0.22); it is not a constant persona-like offset.
  • The graders read the order, but carry less of it into the code. The order is fully visible in every model, but at the point where code starts the graders carry 0.58–0.70 of the untrained model’s order signal (chat answerer 0.95), and that share ranks the 9 models by cheating (Spearman +0.78, exploratory).
  • Hack-exposed graders sit slightly back along the same line (0.86–0.93 of the way from untrained to the honest-only grader), but most of what reviewing hacks changed lies in other directions.
  • The steered model stops talking about the order. Code comments that mention the tests or hard-coding: 27% untrained under the order, 2% steered, 0% for the honest-only grader.

A caveat that changes numbers in the write-up

Under the hack order, the untrained model’s “correct” answers are mostly not honest. Of its % scored correct, % hard-code the shown tests and then add a real solution as a fallback, so they pass the hidden tests too; only % are honest solutions. So the untrained side of the write-up’s “explain only wrote a correct solution 42% of the time, against 20% for the untrained model” is mostly hedges. The graders’ side has not been split for explain only (those adapters were lost); for the honest-only grader in E10 it is 37% honest and 7% hedged of its 44% correct. Before quoting any correct or solved rate under the order (E5–E9), recount with the hack signature (category() in src/rh/make_n14_samples.py; ~6% false positives). Every cheating rate stands.

Designed, not run

  • Corrupt judge (notes/16). An inverted grader trained on the same submissions (hacks → PASS, honest code → FAIL) and a neutral detector (no verdict, just “rule-based” or “example-based”), to ask whether the grader’s attitude carries over. Piloted on 20 reviews in three rounds (pilot page). Closed because of signal: an explained inverted review needs a reason to fail honest code, and the only one left is “less code is better”, a second value the model could learn instead; without explanations the arms differ by one verdict word, which carried nothing in E1. The literature check found the judge-role versions open (research/04).
  • Harmless instructions on the steered model (notes/15). Skipped: E8’s DONE check covers the graders. Whether the steered model still follows harmless instructions is untested.
  • Necessity of the grading shift (E10 Amendment 2). Subtract the shift from the honest-only grader and see whether cheating returns. Proposed with thresholds, not run.
